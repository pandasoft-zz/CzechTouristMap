# CLAUDE.md — Project instructions for Claude

## Language

All documentation, code, and comments must be written in **plain technical English**.
- Keep sentences short and direct
- Avoid unnecessary filler words
- Czech is only used in user-facing strings that are intentionally Czech (e.g. map layer names in the viewer)

## Architecture

- `tiles/` — Planetiler profiles (Java 21, Maven). `BaseProfile` → `base.pmtiles`, `RoutesProfile` → `routes.pmtiles`.
- `relief/build_relief.py` — DTM → `relief.pmtiles` (Terrarium WebP).
- `relief/build_contours.py` — DTM → `data/contours/<part>.gpkg`; Planetiler profile `contours` → `contours.pmtiles`.
- `regions/` — countries and parts. A part is one OSM extract; its files are in `dist/<part>/`.
  `dist/regions.json` is the tile index; `viewer/tiles.js` routes `czmap://` tiles to the part files (ADR 0004).
- `terrain/sonny/` — Sonny's LiDAR DTM tiles of the map area (Git LFS). Do not add tiles outside the map area
  without asking: the LFS download quota is 10 GiB per month.
- `style/` — MapLibre style as JS modules. `style/index.mjs` exports `buildStyle({ variant })`.
  There are two maps: `tourist` (Turistická, default) and `topo` (Topografická, inspired by ČÚZK ZTM10).
  Their themes (colours, widths, labels) are in `style/themes/`, see `docs/style-variants.md`.
  Use the map id in all names: code, files (`dist/style-<id>.json`), render output.
- `sprite/` — style sprite (SDF images, e.g. number shields). Generated by `node tools/czmap.mjs sprite`
  from `tools/sprite.mjs`; do not edit by hand.
- `viewer/` — browser viewer. `tools/server.mjs` serves it and builds `/style.json` on every request.
- `tools/czmap.mjs` — the only entry point for build, serve, render, release.
- `tools/publish-r2.sh` — uploads a release to Cloudflare R2 and switches `latest.json` (docs/publishing.md, ADR 0005).
  `latest.json` is read by the web and the mobile app: keep its format backwards compatible, or raise `schema`.
- `.github/workflows/` — `check.yml` for pull requests, `maps.yml` builds and publishes monthly.

The tile schema is in `docs/tile-schema.md`. Update it when you change a profile.
Architecture decisions are in `docs/adr/`. Add a new ADR when you change a tool or language.

## Map rules

- No POIs in the map. Only land cover, water, transport, buildings, boundaries, names, routes and relief.
- Every PMTiles file must stay under 500 MB (Cloudflare cache limit) and all files together under 10 GB
  (R2 free storage). Check with `node tools/czmap.mjs info` after a build. Split a country into parts when a
  file gets bigger.
- The project name stays "Czech Tourist Map" also with other countries.
- Every style layer needs `metadata.group`: `base`, `relief`, `contours`, `hiking` or `cycling`.

## Workflow for style changes

1. Edit `style/`. Colours are in the theme files in `style/themes/`. Both themes must keep the same shape.
   Mark values without a source with a `no source` comment.
   Do not describe the topo map as a faithful ČÚZK map; it is only inspired by ZTM10.
2. Render and look at the result:
   ```
   node tools/czmap.mjs render --place all --out out/
   node tools/czmap.mjs render --center 15.74,50.736 --zoom 14
   node tools/czmap.mjs render --place praha --compare --size 1600x1200
   ```
   The command fails if the map reports errors (for example an invalid expression).
3. Compare with `docs/design-manual-*.md`.

Rebuild tiles only when the data schema changes: `node tools/czmap.mjs build base` (about 5–10 min).

## Code Style

Follow the rules defined in `.editorconfig` for all files you create or modify:
- Java: 4-space indent, max line length 120
- Python: 4-space indent, max line length 88 (black-compatible)
- JavaScript/CSS/HTML: 2-space indent
- XML: 4-space indent
- All files: UTF-8, LF line endings, final newline
